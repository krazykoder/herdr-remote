Run ./relay/start.sh to get a URL. Setup guide →
Lock Screen alerts when an agent needs you or finishes, even with this closed. On iPhone: open this page in Safari, Share ▸ Add to Home Screen, then enable push from the installed app — iOS delivers push nowhere else.
Each one plays as you switch it on, so you can hear what you are keeping. Push notifications make their own sound — that one is your phone's to silence.
Dark is the default. Light takes the terminal with it.
Prompt turns are blue; detected summaries are orange.
Each section keeps its own separator on the main page. They are shown in the order you switch them on, so turning one off and on again moves it to the bottom. One has to stay on.
How far back Load more will go. A pane opens on its last 200 lines whatever this says, and only what you scroll up for is fetched. Past 1,000 lines the 3-second refresh pauses while you read — scrolling back to the newest line makes it live again.
How much a conversation reads back when you return to it after being away for more than fifteen minutes. Nothing is fetched while you are connected, and neither setting is what the pane draws — this is the record, not the screen. Everything is one read per agent at whatever depth your relay allows, which on a phone over cellular is worth knowing about; a day is 5,000 lines. Recover history in a pane's ⋯ menu always fetches everything, whichever this says.
How often conversations you have not opened are caught up on. A pane you do open catches up the moment you open it, whatever this says, so this is only about the ones you never look at — the other half of a joint thread, mostly. Off means those fill in when you next open them.
Transcripts recorded by an earlier version could fold the same screen in twice. On, each one is repaired the first time it is opened, and says how many copies it removed. Only those: nothing recorded since can hold a duplicate, and the repair is never run on a record that could not have one. Remove duplicates in a pane's ⋯ menu does the same thing by hand.
In a conversation window, the agent you last wrote to and the instruction you last used move to the left end of their rows. Both rows scroll, and the left end is what a phone shows — so what you used last is where your thumb already is. Off holds the rows still: members stay in the order they joined and instructions in the order the list defines, which is the better index once you have learned where things sit.
Shows sent, received and total payload bytes in Activity, newest interval first. Quiet time adds no bucket, so a gap in the record is time nothing was on the wire rather than a row of zeroes. Kept on this device until it is cleared. WebSocket frame and TLS overhead are not available to the page.
A narrower bucket is closer to live, a wider one is easier to read across hours. Changing the bucket clears what has been collected: it is already cut on the old boundaries. Changing how much is shown only changes how far back the table draws.
Turning tracking off stops collecting; what was already recorded stays on this device until this throws it away. Per-pane totals go with it.
Off by default. Both composers type into an agent's prompt, where a flag is not a typo and a path is not a sentence — a keyboard that capitalises the first word of one has changed it. On gives you the phone's own correction, capitalisation and spellcheck for writing prose to an agent. A terminal's composer never takes it either way: there it is a command line.
Off by default. On shows a microphone beside the composer; it needs https and a browser with speech recognition.
